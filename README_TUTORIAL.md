# Инструкция по запуску проекта «Система управления закупками»

## Что реализовано

- ПР1: `pr1/main.py` с функцией, `if/else` и `datetime`; README и `.gitignore`. Корневой `main.py` сохранён как консольное приложение для следующих работ.
- ПР2: списки/словари, JSON-хранилище, функции и pytest-тесты.
- ПР3: классы предметной области `Product`, `Supplier`, `Application`, `PurchaseOrder`, сериализация JSON.
- ПР5: Django-проект и приложения, URL-маршрутизация, страницы и обработчик 404.
- ПР6: общие шаблоны `base.html`, `include`, `extends`, циклы, `{% url %}`, CSS и JavaScript-статика.
- ПР7: отдельная схема SQLite, импорт JSON через `executemany`, SQL-запросы и чтение бизнес-данных через `sqlite3`, без Django ORM для сущностей закупок.

Django всё равно использует свою систему миграций для служебных таблиц (пользователи, сессии и т. п.). Бизнес-таблицы создаются через `sql/schema.sql`.

## 1. Подготовка окружения

Нужен Python 3.10+ (рекомендуется Python 3.12 или 3.13). Откройте терминал в папке, где находится `manage.py`.

Windows:
```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

macOS / Linux:
```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

## 2. Создание базы и импорт данных

Из корневой папки проекта выполните:
```bash
python -m db.import_json
```
Команда создаёт `data/purchases.sqlite`, применяет `sql/schema.sql` и импортирует товары, поставщиков, заявки и заказы из `data/*.json`. Повторный запуск импорта очищает и заново загружает бизнес-таблицы.

## 3. Служебные таблицы Django

```bash
python manage.py migrate
```
Команда нужна, даже несмотря на то, что предметные таблицы закупок обслуживаются вручную через `sqlite3`.

## 4. Запуск сайта

```bash
python manage.py runserver
```
Откройте `http://127.0.0.1:8000/`.

## 5. URL для ручной проверки

- `http://127.0.0.1:8000/` — главная и сводные счётчики.
- `http://127.0.0.1:8000/products/` — каталог товаров.
- `http://127.0.0.1:8000/products/1/` — карточка товара с ID 1.
- `http://127.0.0.1:8000/suppliers/` — поставщики.
- `http://127.0.0.1:8000/applications/` — заявки.
- `http://127.0.0.1:8000/orders/` — заказы.
- `http://127.0.0.1:8000/orders/by-date/?date=2026-01-01` — фильтр заказов по дате.
- `http://127.0.0.1:8000/несуществующая-страница/` — проверка страницы 404.
- `http://127.0.0.1:8000/admin/` — стандартная административная панель Django (при необходимости создайте суперпользователя командой `python manage.py createsuperuser`).

## 6. Тесты и стиль кода

```bash
python -m pytest
flake8
```
Тесты проверяют основные операции предметной области и сохранение/загрузку JSON. Проверка `flake8` может сообщать о длинных строках в SQL/конфигурации, если правила локальной версии отличаются; основной лимит задан в `.flake8`.

## 7. Важные замечания

- Проект намеренно не использует Django ORM для таблиц товаров, поставщиков, заявок и заказов: это требование ПР7.
- `data/purchases.sqlite` — генерируемый файл базы. Если его удалить, снова выполните импорт JSON, затем `migrate`.
- Для учебного локального запуска `DEBUG=True` и тестовый `SECRET_KEY` оставлены включёнными. Не публикуйте этот вариант как production-сайт.
